## 3. Caveats

1. **Solver Algorithm Implementation Scope**:
   - The implementation of the Two-Phase Kociemba / arbitrary 54-sticker solver engine falls under Requirement R1 (Explorer 1's domain). This report outlines the exact synchronization interface and contracts required for Step 3 to consume that solver.
2. **Webcam Lighting Variations**:
   - Camera sticker detection relies on HSV thresholding in `colorDetector.ts`. Under severe colored lighting (e.g. low-CRI warm incandescent bulbs or tinted screen glare), orange and red or yellow and white may require manual color correction via the 2D review net before proceeding.
3. **Hardware Acceleration**:
   - Tested on standard desktop WebGL2. On low-end mobile devices without WebGL2, WebGL1 fallback will render correctly, but shadow maps (`PCFSoftShadowMap`) should be monitored for performance.

### 4.1 Summary of Architectural Synchronization Failures

| ID | Location | Severity | Description |
|---|---|---|---|

| **SYNC-7** | `ThreeCubeViewer.tsx` | **Moderate** | WebGL Context & Buffer Leak: Box geometries, materials, shadow textures, and canvas are not disposed during unmount, causing WebGL context exhaustion over multiple tab switches. |

### 4.2 Step-by-Step Fix Strategy & Architectural Recommendation

#### Step 1: Implement Live Mathematical State Tracking in Step 3
In `Step3SolveInteractive.tsx`, compute the true mathematical state at step $k$:
```typescript
const currentCubeState = useMemo(() => {
  if (!scannedCubeState) return SOLVED_CUBE;
  let state = cloneCube(scannedCubeState);
  const movesToApply = allMoves.slice(0, currentMoveGlobalIdx);
  for (const m of movesToApply) {
    state = applyMove(state, m.move);
  }
  return state;
}, [scannedCubeState, allMoves, currentMoveGlobalIdx]);

const isActuallySolved = useMemo(() => isCubeSolved(currentCubeState), [currentCubeState]);
```
- Pass `isActuallySolved` into `ThreeCubeViewer`.
- Display "100% SOLVED ✓" and celebratory animations **if and only if** `isActuallySolved === true`.

#### Step 2: Fix "Practice in 3D" Setup in Algorithm Library
When `customAlgorithm` is present:
- Compute setup state:
  ```typescript
  const setupState = applyScramble(invertMoves(customAlgorithm.notation));
  onUpdateScannedCube?.(setupState);
  onSetDemoScramble?.(null);
  ```
- When the user steps through the algorithm to the end, the cube naturally transitions to `SOLVED_CUBE`, and `isActuallySolved` becomes `true`!

#### Step 3: Integrate Camera Scanner to Step 3 Seamlessly
In `Step2CameraScan.tsx` `handleProceedToStep3`:
1. Validate that all 6 faces are verified and the 54-sticker state is valid (`validateCubeNetState(cubeNetData)`).
2. Clear `demoScramble`: `onSetDemoScramble?.(null);` and `localStorage.removeItem('cubemaster_demo_scramble');`.
3. In `Step3SolveInteractive.tsx`: When `scannedCubeState` is provided and `demoScramble` is null:
   - If `isCubeSolved(scannedCubeState)`: Display "Khối Rubik của bạn đã ở trạng thái hoàn thành! (0 Moves)".
   - Else: Invoke the solver engine (R1) to generate the real step-by-step solution for `scannedCubeState`.

#### Step 4: Synchronize Animation Timing & Speed Scaling
1. Pass `playbackSpeed` to `ThreeCubeViewer`:
   - Duration mapping: `0.5x` -> `380ms` (smooth learner pace), `1.0x` -> `180ms`, `2.0x` -> `110ms` (snappy speedcube pace).
2. Postpone completion callback: In `ThreeCubeViewer`, fire an `onAnimationComplete` callback when the final move finishes, and only then trigger confetti and audio!

#### Step 5: Fix WebGL Lifecycle & Tab Navigation Leaks
In `ThreeCubeViewer.tsx` cleanup return function:
